这个端点是什么

MCP Streamable HTTP

/mcp 是 Smriti 的机器接口：MCP 客户端把 JSON-RPC 2.0 请求用 POST 发过来，用它读写持久偏好。它不提供网页，也没有可以点开的界面。

传输
Streamable HTTP
协议
JSON-RPC 2.0
方法
POST仅此一个方法，响应头声明 Allow: POST

六个工具

工具名与参数由 src/mcp/server.ts 注册，调用参数一律 snake_case。
工具 做什么
memory_search 在已保存的偏好里检索。query 必填，topic 可选，limit 默认 10、上限 50。
memory_get 按 topic 与 id 读一条；不存在时返回 memory: null。
memory_topics 列出 12 个固定主题词表，以及每个主题的条目数。
memory_upsert 写入一条偏好。冲突或近似重复时不覆盖，返回 status=pending_review 并生成待裁决变更；可用 idempotency_key 安全重试。
memory_list 列出偏好。topic 可选，limit 默认 50、上限 200。
memory_forget 软删除一条：移入 history 保留 30 天，返回是否命中。reason 必填。

和 /ui 的分工

看板 /ui
给人看。记忆、待裁决、主题，只读；写入与裁决在这里没有按钮，它们属于 dsh 命令和 MCP 工具。
端点 /mcp
给模型和客户端用。dsh 插件通过它读写；两个入口共用同一份 R2 真源，看板读到的就是工具写下的。

为什么浏览器打开会看到 405

GET /mcp

地址栏回车发的是 GET，它是一次页面导航，不是一次 MCP 调用。MCP 客户端只向 /mcp 发 POST 的 JSON-RPC，所以服务器按 HTTP 方法语义拒绝其它方法：405 Method Not Allowed，并在响应头里声明 Allow: POST。

同一个 405 有两种响应体：浏览器（Accept 含 text/html）拿到的就是本页；curl 和 MCP 客户端拿到的仍是 JSON 错误。状态码的含义不变——方法不对，不是服务坏了。

判断服务是否活着，请请求 GET /healthz（免鉴权，返回 {"ok":true}）；/mcp 的 405 不是健康检查的信号。

initialize 与 tools/call 的标准顺序

自己写客户端时，按 MCP 的顺序发请求；官方 SDK（包括 dsh 插件用的客户端）会替你做前三步。

  1. initialize：带上 protocolVersion（当前按 2025-06-18 握手）、capabilities 与 clientInfo；服务端回 serverInfo（name 为 smriti）。
  2. notifications/initialized：一条通知，没有 id，不需要等响应。
  3. tools/list：拿到六个工具和各自的输入 schema。
  4. tools/call：{"name":"memory_search","arguments":{"query":"包管理器"}}，参数名用 snake_case。

服务端是 Streamable HTTP 的无状态实现，不返回会话 id；请求按顺序发即可，不要并发跳过 initialize。

常见错误码

响应体里的 code

错误统一为 {"error":{"code","message"}}，先看状态码，再看 code。
状态码与 code 含义 排查方向
401 unauthorized 请求没过 Cloudflare Access：缺少或无效的 Cf-Access-Jwt-Assertion。 确认请求经过 Access 应用；workers.dev 域名不经过 Access，要用自定义域名；Access 应用的策略覆盖到 /mcp；service token 属于该应用。
500 auth_misconfigured Worker 没配好 Access 校验：缺 ACCESS_TEAM_DOMAIN 或 ACCESS_AUD。 wrangler secret list 核对两个 secret；确认 AUTH_MODE 不是 dev；补上后重新部署。
405 method_not_allowed 对 /mcp 用了 POST 以外的方法——包括浏览器直接打开，也就是本页。 客户端改用 POST 发 JSON-RPC；健康检查改用 GET /healthz。
404 not_found 路由没匹配：路径或方法写错。 核对路径是 /mcp（没有尾斜杠），以及 POST /v1/… 与 GET /v1/… 的方法是否对得上。
503 assets_unavailable ASSETS 静态资源绑定缺失或取不到：/ui 的页面与静态文件不可用。 检查 wrangler.jsonc 的 assets 配置与部署产物里的 public/；/mcp 有内联兜底页，JSON-RPC 不受这一项影响。

接下来

装进 dsh

  1. 安装 Smriti-DSH 插件：先 pnpm run build，再 dsh plugin add <本机路径或 GitHub 仓库>；在插件配置里填 gatewayUrl，把 service token 写入 credentials 的 CF_ACCESS_CLIENT_ID / CF_ACCESS_CLIENT_SECRET。
  2. 确认工具出现：重启 dsh，工具列表里应出现 mcp__smriti__memory_search 等六个工具，前缀全部是 mcp__smriti__。
  3. 裁决仍走命令：冲突进入待裁决后，在 dsh 里用 /memory review 逐条看，用 /memory approve <changeId> 批准；页面上刻意没有裁决按钮。

部署、Access 与插件配置的完整步骤见仓库 README；回到 /ui 可以核对工具写下的记忆是否已经出现。

响应状态码固定为 405，并声明 Allow: POST：这是方法语义，不随页面内容改变。本页只是把「为什么」和「怎么接」写清楚。
